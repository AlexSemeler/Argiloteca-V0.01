Argiloteca search guide

Learn how to search the collection for clays, clay minerals, analytical techniques and publications. Click the examples to open these queries in the Argiloteca search.

Records use Portuguese and English mineral names. Try both forms: {{ example('caulinita OR kaolinite') }} or {{ example('esmectita OR smectite') }}. Results depend on the available records and selected filters.

Simple search: one or more terms

Example: {{ example('caulinita esmectita') }}

This query finds records containing caulinita or esmectita in searchable fields. These are the Portuguese names for kaolinite and smectite. It is equivalent to {{ example('caulinita OR esmectita') }}. Entering two words without an operator does not require both words to be present.

Require terms to be present

Use AND or put + before each required term. Write the operators AND, OR and NOT in uppercase, including queries that use Portuguese terms.

Example: {{ example('caulinita AND esmectita') }}

To find records mentioning kaolinite and X-ray diffraction (XRD, or DRX in Portuguese), use {{ example('kaolinite AND "X-ray diffraction"') }} or {{ example('+kaolinite +"X-ray diffraction"') }}.

Exclude terms

Examples: {{ example('kaolinite NOT halloysite') }} or {{ example('+kaolinite -halloysite') }}

These queries require kaolinite and exclude records that also contain halloysite. Use NOT or - to leave terms out of the results.

Search for a phrase

Example: {{ example('"X-ray diffraction"') }}

Quotation marks search for the terms in the same sequence. They are useful for techniques such as X-ray diffraction or phrases such as {{ example('"clay minerals"') }}.

Search a specific field

Example: {{ example('metadata.title:kaolinite') }}

The prefix metadata.title: restricts the query to the title. Use parentheses to group several terms in the same field: {{ example('metadata.title:(kaolinite OR smectite)') }}.

These fields can help refine your search:

  • metadata.title: record title.
  • metadata.description: description or abstract.
  • metadata.publication_date: publication date.
  • metadata.resource_type.id: resource type identifier.
  • metadata.subjects.subject: text of the declared subjects.
  • metadata.identifiers.identifier: declared additional identifiers, such as a DOI from an external source.

For example, {{ example('metadata.resource_type.id:dataset AND kaolinite') }} restricts the search to datasets mentioning kaolinite. Keep field names and the identifier dataset exactly as written.

Combine terms, fields and dates

Example: {{ example('metadata.title:kaolinite AND metadata.publication_date:[2020-01-01 TO 2025-12-31]') }}

This query requires kaolinite in the title and limits the publication date to January 1, 2020 through December 31, 2025. You can combine simple searches, quoted phrases and field searches in the same query.

Search a date range

Example: {{ example('metadata.publication_date:[2020-01-01 TO 2025-12-31]') }}

Use dates in YYYY-MM-DD format and write TO in uppercase. Square brackets [] include the boundary dates; curly brackets {} exclude those boundaries. An asterisk denotes an open boundary.

  • {{ example('metadata.publication_date:{* TO 2020-01-01}') }}: publications before January 1, 2020.
  • {{ example('metadata.publication_date:[2020-01-01 TO *]') }}: publications from January 1, 2020 onward, including that day.

Partial dates expand to the start of the period: 2020 becomes 2020-01-01, and 2020-06 becomes 2020-06-01. To cover a whole year, specify the starting and ending dates explicitly.

Sort the results

Use the sorting options in the results list to choose the best match, newest records or oldest records. Best-match sorting considers the relevance of your query terms. Search filters let you refine the set of results.

Search patterns with regular expressions

Example: {{ example('metadata.identifiers.identifier:/10[.]17632.*/') }}

This example searches additional identifiers beginning with 10.17632, the DOI prefix used by Mendeley Data. In a regular expression, [.] represents a literal dot and .* matches the remaining sequence.

The pattern must match the entire field value. This field differs from pids.doi.identifier, which holds the record's own DOI: the DOI of an imported publication may be stored among its additional identifiers.

Find populated or missing fields

With a declared subject: {{ example('_exists_:metadata.subjects.subject') }}

Without a declared subject: {{ example('NOT _exists_:metadata.subjects.subject') }}

Use _exists_: to require a value in a field and NOT _exists_: to find its absence. A declared subject does not mean that all other metadata fields are complete.

More search features

Give a field more weight

Example: {{ example('metadata.title:kaolinite^5 OR metadata.description:kaolinite') }}

The operator ^5 gives an occurrence in the title more weight than one in the description. It affects best-match sorting without changing record metadata.

Search for an approximate spelling

Example: {{ example('kaolinte~') }}

The operator ~ searches for similar spellings, such as kaolinite in this example. It can help with a typing error; check the terms found.

Allow proximity between words

Example: {{ example('"clay minerals"~3') }}

The number after the phrase allows more flexibility in term positions than the same phrase without ~3. It can find the words near each other even when other words appear between them.

Use wildcards

Examples: {{ example('kaolin*') }} and {{ example('smectit?') }}

The asterisk * replaces zero or more characters; the question mark ? replaces a single character. For example, kaolin* may find terms such as kaolinite, and smectit? may find smectite. Wildcard searches can be slower; use a complete term when you know its spelling.
